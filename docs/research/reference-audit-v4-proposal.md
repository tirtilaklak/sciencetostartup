# Reference v4: genuine first-peer initial-hypothesis retention

Coordinator integration stages explicit version dispatch, the context-5 owned
recipe and offline frozen-receipt verification. Independent combined-code review
and actual method adoption remain separate. New public audit checks inspect
dynamic field names as well as values and keep untrusted names out of structural
diagnostics. Historical v3 and v2 readers retain their original behavior.
Rejected artifact-authentication diagnostics use ordinal positions, and caught
exception text passes the same public privacy boundary. Frozen verification
compares the public export with its manifest-bound source-context graph and
checks available sampled source, entity, status and review attachments. Public
group-review projections are context-bound; their opaque original private
record hashes are authenticated by the admitted receipt rather than falsely
reconstructed from narrowed public notes.

**Proposal only.** This adds a separate reader/schema, not method adoption, a
selected current panel, a truth run, a successful audit, a trusted admission or
publication approval. The code and tests do not inspect the actual population,
candidates, frame, gold or scores. Fixtures are invented in memory and explicitly
labelled `FIXTURE_ONLY`. Private receipts made by tests are `fixture: true`.

The endpoint remains the actual unchanged `research_graph.public_graph`. The new
evaluation kind is `source_bound_initial_hypothesis_disposition_holdout`;
audit/receipt/admission versions are respectively `reference-audit-v4`,
`reference-private-validation-v4`, and `reference-audit-admission-v4`. Historical
v2/v3 readers, schemas, artifacts, failures and results remain unchanged. Nothing
in v4 clears or retargets the held v3 baseline or its exact-source/privacy errors.

## Population and unit

An actual independent method adoption must expressly accept one uniform rule:
`first_peer_submitted_substantive_hypothesis_per_semantic_lineage`. The rule was
proposed after ordinary production review, which must be disclosed. Apply it to
the entire genuine nonhistorical input population, including older eligible
findings, rather than just selected REVISE drafts. Count exactly the original
first peer-submitted hypothesis in each eligible scientific lineage, retaining
its exact scientific digest, wording, evidence, source IDs and actual current
production disposition. It must still exist in the genuine input. An unavailable
earliest hypothesis or missing provenance remains held; a corrected successor
cannot replace it or add a second case. All successors, exclusions and unresolved
matches remain in the full population crosswalk and original histories.

The full curation covers every nonhistorical assertion once. Each row has
`assertion_id`, `lineage_sha256`, `disposition` (`include`, `exclude`, `held`),
`scope_kind`, `finding_equivalence_sha256`, and a retained `reason`. Substantive
scope, meaningful scientific units, semantic equivalence, creator identity and
complete exposure reconciliation require actual independent human/agent work.
The code checks byte authenticity, coverage and consistency; hashes, IDs,
filename patterns, booleans and prose do not establish that work occurred.

Do not atomize repeated table cells, titles, metadata, identities, version links,
paraphrases or paper/dataset aliases to fill the panel. Do not create evaluation
negatives, change production status, drop inconvenient hypotheses, or select
using source-truth outcomes. Ordinary production reviews are observations, never
fresh audit gold. A source-supported initial draft that was prudently withheld or
corrected is FN under this endpoint. An unsupported withheld initial draft is TN,
even when a later supported correction is emitted. Corrected output does not earn
additional TP credit here.

## Original lineage and source identity

`lineage_manifest` binds `population_rule`, the canonical exact input graph hash,
and `lineages`. Each lineage has `lineage_sha256`, `first_assertion_id`, all genuine
nonhistorical `member_assertion_ids`, an original production `history_ref`, and
`submissions`. Each submission contains its `assertion_id`, original
`first_peer_submitted_on`, `submission_ref` and `peer_receipt_ref`. History and
submission references name supplied retained artifacts and exact original JSON
entries: `{artifact_id, entry_pointer, entry_sha256}`. They do not discover paths
or accept an explanation in place of original bytes.

The submission entry preserves the original `assertion` and every exact cited
`sources` record. Its separately retained receiving-peer entry records
`event: peer_submission`, `assertion_id`, `scientific_sha256`,
`submission_entry_sha256`, exact `source_record_sha256`, `received_on`, actual
receiver `invocation_id`/`reviewer`, `actual_execution` and `fixture`. The earliest
unambiguous actual received time determines the initial case. All current members
need authenticated submission provenance before an included lineage can count;
an earlier original outside the genuine current input holds that lineage. Exact
production review originals remain bound through the frozen graph/bindings.
Actual receiving-peer reviews cannot predate the recorded first peer opening;
the author's legitimate earlier source-review completion is preserved and is
not a receiving-peer event. Reviewers must inspect the
original history, complete missing/older-version exposure and semantic matches;
the reader cannot infer an omitted real event from a self-declared list.

An additive `derived_grouped_packet_v1` submission representation preserves
genuine historical batch formats without inventing atomic old receiving events.
It records its real current `derived_on`, an original assertion `submission_ref`
and exact `source_refs` into the same genuinely opened packet. The original raw
grouped start/receipt remains `peer_receipt_ref`; an empty JSON pointer denotes
the complete original JSON document. `peer_opening_ref` points to its original
start-time value. `packet_digest_ref` points to the exact packet-byte digest in
that original receipt or its authenticated sealed index. A
`group_authentication_ref` preserves the actual prior independent authentication
of that group: original packet pin, both role-opening times, earliest role/time,
and original receiving/sealed artifact pins. The reader cross-checks those
original bytes and chooses the earliest actual peer role, never a completion or
the bridge's creation time. An absent old invocation identifier stays absent;
the bridge creates no old `actual_execution`, reviewer or atomic-receipt claim.
Original artifact entry hashes, rather than invented normalized old records,
remain the frame's submission/receiving commitments. The earlier atomic format
continues to work unchanged.

The declared earliest role must have the minimum of the two actual start times.
The receiving-entry commitment must contain its opening and any same-artifact
packet binding, using decoded JSON-pointer ancestry rather than textual prefix
matching, including closed-map aliases for the same exact receiving bytes.
A current derived representation must precede its actual new population
ACK and frozen input/frame; original scientific and creator reviews retain their
earlier real dates.

An included lineage may retain `authenticated_successors` with exact current
successor ID/scientific identity, a retained independently authenticated original
correction `chain_ref`, and the exact later original `opening_ref`. The original
chain must bind the initial ID/digest/time, successor ID/digest and actual later
opening-artifact bytes. These successors remain genuine full-input members and
can never become additional counted cases or reset the initial opening. This
format does not manufacture atomic receipts for old grouped correction work.
Each successor's attached receiving-peer reviews must also follow that successor's
own authenticated opening. Its author's earlier legitimate work remains allowed.
Missing or contradictory initial/chain proof still holds.

Any normalized population or metadata-review projection created now is explicitly
current and derived. Its previous original acceptance, decisions and times remain
immutable. A real new independent representation-consistency ACK may bind the
new exact mappings and preserved accepted originals before future input/frame
freeze; the projection must never pretend that ACK or the new reader-format
entries existed during the old actual review. This is a bounded interface check,
not another source-science or case-eligibility reading gate. Pending ACKs keep
the private execution-validation interface incomplete rather than fabricating
old review metadata.

An isolated metadata exception can preserve that original scientific identity:
unsupported `documentation` may become `repository` for an exact creator GitHub
README/LICENSE, `dataset_card` for an exact creator Hugging Face card, or
`provider_documentation` for an exact creator protocol report. All other source
fields must be byte-equivalent as JSON values: URL, title, publisher, version,
body response digest, capture, excerpt/digest, locator, license and all other keys.
The assertion scientific digest, evidence, actual reviews and first-peer times
remain exact. Scientific/evidence changes require a distinct successor and cannot
be normalized by this exception. This code does not approve any source or claim.
An immutable Hugging Face card may use the original `blob`, `raw` or `resolve`
route; the exact creator/card review and every other source field remain required.

`metadata_adaptations.records` contains each `source_id`, exact `before_record`
and `after_record`, the allowed `artifact_kind`, `author_invocation_id`, original
`creator_identity_ref`, and one or more original independent `review_refs`.
Each original review binds the source ID, both record hashes, artifact kind,
creator-evidence hash, actual reviewer/invocation/time/fixture metadata, and
`decision: metadata_only_creator_artifact`. Its reviewer differs from the
transformation author. Every actual production mapping needs that independent
content/creator review; a domain or path alone supplies no approval.

## Exposure and independent population review

The immutable exposure registry retains assertion IDs, scientific digests,
finding-equivalence keys and lineage keys. It authenticates all old250, old226,
citation62, actual held-v3 200, and 88-repair originals under source-artifact keys
`reference250`, `reference226`, `citation62`, `reference200`, `repairs88`, plus the
actual `exposure_semantic_review`. Same-body sibling/scoped sources, known
correction chains, audit-targeted fixes, wording changes and semantic equivalents
stay exposed. Missing or unresolved matching remains held. A new digest or ID
cannot supply freshness. The code cannot independently certify semantic registry
completeness; actual review and separate trusted admission must do so.

`population_semantic_review` binds exact canonical input and byte hashes of
`frame_curation`, `lineage_manifest`, `exposure_registry`, `metadata_adaptations`,
`exposure_semantic_review`, and the canonical exposure-scope pin map. It contains
an `author_invocation_id` and one or more retained original `review_refs` from a
separate actual population/exposure review invocation before frame freeze. Each
original review binds those same inputs and covers every population row once,
with assertion/lineage/history hashes, curation-entry hash, disposition,
scientific-equivalence key, scope kind and `exposure_decision` (`unexposed`,
`exposed`, `unresolved`). Every included row must be independently `unexposed`.
The independent review cannot be the curation author, a production review or a
fresh audit/SUT invocation. Excluded and held rows remain visible and add no N.
There is no invented additional two-reviewer gate for this neutral curation.

## Prospective freeze, actual SUT and fresh truth

Adopt the exact rule/code/policy and the fixed new seed
`STS-reference-initial-peer-hypothesis-v4-prospective-2026-11-12` before selecting
or running. Freeze exact input, complete reviewed curation/lineage/exposure,
metadata adaptations, source-only packet, frame and deterministic panel. Order
within genuine disposition strata by SHA256(seed + newline + original assertion
ID). Take `min(100, actual withheld availability)` and fill exactly 200 from
included initial hypotheses. This retains the v3 design; there is no invented
minimum of 50 or 100 withheld. Zero genuine withheld remains a hold. Natural N
below 200 remains incomplete without fillers, seed search or substitutions.

Chronology is strictly `method → input → frame → panel → actual SUT → sealed
predictions → fresh truth → sealed truth → outcomes opening → score`. Run and
seal the real unchanged projection on exact full frozen input before either
truth run. The projection helper returns actual execution bytes; later replay is
only an integrity check and never a newly fabricated pre-truth run.

Two different fresh source/adversarial truth invocations independently inspect
pinned primary sources, blind to production status/predictions, old judgments and
each other's decisions. Record requested model/reasoning and honestly record
runtime model as `unknown` unless actual retained runtime attestation exists.
Prior neutral source preparation may be supplemental and honestly disclosed,
including preparation before method adoption. Do not retimestamp it or call a
hash-only check a fresh full-source read.

Each fresh truth run requires an actual post-start `source_context_recheck` with
exact response/scoped-evidence records, followed by its own frozen source notes,
then `hypotheses_opened_on`, then `decisions_started_on` and actual completion.
Recheck/notes originals bind run ID, source-packet digest and real times. Both
contain exact `source_id`, `response_sha256`, `locator`, `reading_scope_sha256`
records for each used adjudication scope, and disclose the original supplemental
preparatory-notes hash or null. Preparatory originals authenticate separately;
only the actual new post-start contextual work satisfies the new chronology.
Actual scientific reading remains independently reviewed work, not a regex test.

Each truth entry binds only the frozen hypothesis's exact cited source IDs,
scientific digest, original independent decision entry and actual run envelope.
Same response bytes at another scoped source ID cannot rescue the hypothesis.
Both original decisions and critical-materiality judgments are retained. A real
independent source-grounded tie invocation is required for disagreement. Unknown
and unresolved critical materiality remain in the selected panel and hold it.

## Private validation, trust and live applicability

New method commitments are `population_rule`, `curation_sha256`,
`lineage_manifest_sha256`, `population_review_sha256` and
`metadata_adaptations_sha256`, in addition to unchanged SUT/input/source-packet
and adoption/policy commitments. Frame rows also bind lineage/history, original
submission/receiving-peer entry hashes and actual first-peer time.

`validate_private_reference_v4` requires independently retained closed artifact
pins, all original payloads, full frozen input/output/SUT execution, curation,
lineage/history/submission/receiving-peer originals, population/exposure review,
metadata-adaptation/creator/review originals, all five exposure scopes, adoption,
source-only packet, actual new contextual rechecks/notes, independent truth/tie
originals and every distinct selected raw source response. Additional artifacts
referenced by any entry belong in the closed map. It reconstructs the complete
original frame, exact selection/bindings and unchanged SUT output. Its receipt
preserves every error, includes a population-authentication commitment, and never
creates or accepts a trust admission.

`validate_public_reference_v4` requires exact audit/receipt bytes, complete current
input for selected included and withheld bindings, and caller-trusted independent
admission. Admission explicitly accepts the exact population rule and lineage,
population-review and metadata-adaptation hashes. Validator/schema/SUT/helper/
dispatch source pins remain exact. A fixture receipt is inadmissible even when
all its mechanical checks succeed. A projected public graph cannot reconstruct
private withheld hypotheses. Frozen archival replay is a distinct explicitly
admitted historical scope, not live applicability or a hidden private fallback.

Live applicability retains v3's bounded behavior: unrelated later records and
additional review links may coexist with the admitted frozen panel. Every
selected scientific/source/entity/status/output/original-review binding must
remain exact; later research never retargets the frozen population or membership.
A newly attached selected-case review predating the admitted first-peer event is
a hold. New independent evidence of an earlier hypothesis, undisclosed exposure,
semantic equivalence, lineage error or other integrity contradiction must hold or
revoke caller-trusted admission. Graph-ID comparisons cannot certify that such
semantic evidence is unrelated. Future coordinator integration must preserve
these holds and cannot use an old admission to ignore known contradictory facts.

Raw TP/FP/FN/TN/Unknown and precision/recall denominators are recomputed, with
unchanged 200/.98/.95 floors, zero critical false attribution, nonzero genuine
withheld and no Unknown/unresolved-integrity holds. Report actual supported-
withheld availability and small-k limits: when all 200 are supported, withholding
all k gives recall `(200-k)/200`; k≤10 cannot fail the .95 floor. These are finite
initial-assertion-panel retention metrics. They establish neither population,
extraction/discovery recall nor source-quality precision over all corrected final
output. Publication, coverage, privacy, edition cutoff, scientific approval,
archive and technical gates remain separate.
